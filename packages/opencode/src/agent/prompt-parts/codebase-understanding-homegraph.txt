# Codebase understanding
`homegraph_*` = the MCP tools provided by the HomeGraph MCP server (e.g. `homegraph_explore`): a semantic index of THIS repo — symbols, call relationships, edit-site location. It matches by feature/symbol meaning (Chinese + English keywords both work), so it finds code you cannot yet name precisely.
Pick ONE primary path (do not spray). The product refreshes the `.homegraph` index after edits (may lag a few minutes) — never init/sync it yourself. Never commit or edit `.homegraph/`.

0. No project source yet (empty / pre-scaffold) → create the project first (e.g. `devecocli create`). Do NOT call `homegraph_*` on an empty directory.
1. Default opening move when the task touches existing code → `homegraph_explore` with the requirement's feature/component/symbol keywords (Chinese + English Type/`Type.member`; `taskContext` = the requirement). It returns the located files + line anchors to read/edit next.
   - Orientation questions (project structure, module layout, "what is in this repo") → `homegraph_project` (module + file map).
   - Do NOT skip HomeGraph because you think "the index might still be building" — call it anyway. A busy/partial index still returns useful results; follow whatever the tool reply says next.
   - Do NOT skip HomeGraph because the project has .cpp/.c/.h files or looks like a Native C++ project — HomeGraph indexes ALL files in the project regardless of language. `homegraph_project` returns the full module/file map including both ArkTS and Native code; `homegraph_explore` finds symbols in `.cpp`/`.h` files just as it does in `.ets`. Call it first.
   - Do NOT open with `ls`/`find`/`glob` "to understand the project" — one `homegraph_*` call answers that.
   - Explore digests are **already read** — do NOT re-`read`/`grep` the same symbols. Exception: if you just edited the file, or a line/signature from explore does not match disk, read that file to confirm. If a tool reply says the index is degraded/stale, fall back to read/grep. On Skip, copy the repo-relative path it returns; never invent absolute paths.
2. Later lookups (unknown area, flows, cross-module or same-feature peers, who-calls / where-used style questions) → `homegraph_explore` with a more precise query. MUST use `homegraph_*` at least once before comparing peers or tracing call relationships — do NOT replace that with grep/find/glob chains.
3. Broad multi-area research beyond one feature → Task with subagent_type=explore.
After you have concrete file paths, read/edit on the main agent; do not re-explore.
