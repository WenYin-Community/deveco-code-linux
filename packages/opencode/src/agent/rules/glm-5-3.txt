# ArkTS / ArkUI codegen rules (glm-5.3)

Ordered by how often each class actually breaks the build. Scan this before writing `.ets` files, and again before calling `devecocli check arkts`.

## Imports and exports
- Import only real `@kit.*` members. Never invent an export or subpath, never use a relative or synthetic Kit path (`.ArkUI`, `./ArkUI`, `ArkUI`), and never import `.ets` from `.ts`/`.js`. `@kit.ArkUI` does NOT export `ObservedV2`, `Trace`, `Resource`, `ResourceColor`, or `NavPathStack` — decorators are global and the rest are global types.
- `router` comes from `@kit.ArkUI`; every page calling `router.*` must import it. Import `BusinessError` only from `@kit.BasicServicesKit` or `@ohos.base` — business Kits do not export it.
- Anything referenced across files needs `export`; `declares 'X' locally, but it is not exported` means the keyword is missing. Match the import form to the export form: a file with named exports needs `import { X } from './X'`, not a default import. Never import a member from the file that defines it.

## Page and component structure
- `build()` and `@Builder` bodies hold UI component syntax only: no local declarations, no `if`/`switch`/ternary, no state mutation, no calls to non-`@Builder` methods.
- Do not name a `CustomComponent` member `width`/`height`/`size`/`visibility`/`opacity`/`brightness`/`contrast`/`backgroundColor` — they collide with inherited attribute methods. Use a distinct name like `cardWidth`.

## Navigation routing
- Prefer the system route table: declare each destination in `resources/base/profile/router_map.json` (`routerMap` array: `name` + `buildFunction` + `pageSourceFile`), reference it from `module.json5` via `"routerMap": "$profile:router_map"`, and export `@Builder export function XxxBuilder()` in the page file. Hand-written `.navDestination(builder)` is a fallback for trivial single-level cases only.
- A route table and a hand-written `.navDestination(builder)` are mutually exclusive — once `module.json5` declares `"routerMap"`, the table resolves every pushed destination on its own, so do NOT also attach `.navDestination()`. Keeping both is redundant: the builder re-declares the table's `name`→page map in a second place (drift/maintenance hazard), and `pushPathByName` already lands on the route-table page. Pick exactly one mechanism per `Navigation` host; if a route table exists, drop the builder entirely.
- If `.navDestination()` is used at all, it must be ONE builder containing the full if/else name→page map. Chaining `.navDestination()` twice makes the last call overwrite every earlier registration — all pushed routes land on one wrong page (white screen at runtime), with no compile-time diagnostic.
- A destination page's `build()` must have `NavDestination` as its root node — a page pushed by name but not rooted in `NavDestination` renders blank/fails to mount.
- A `NavDestination` page may keep `navPathStack: NavPathStack = new NavPathStack()` only as a placeholder. Assign the host stack in `NavDestination().onReady((ctx: NavDestinationContext) => { this.navPathStack = ctx.pathStack })`, and read params from `ctx.pathInfo.param`. `onReady` runs only when this component's root is `NavDestination`.
- The child inside `Navigation(this.navStack)` is not a `NavDestination`, so `onReady` never runs there. Pass that same stack in: `HomePage({ pathStack: this.navStack })` (a plain field or `@Param`). In the click handler, not in `build()`, `this.queryNavigationInfo()?.pathStack` is the same object. A second `new NavPathStack()` on the home is a different stack: the home stays mounted and the destination never appears. Do not `.catch(() => {})` on `pushDestination` or `pushPathByName`. Do not pass the stack with `@Provide`/`@Consume` or `AppStorage.setOrCreate`/`AppStorage.get` — another component reading that stack during first-frame render and calling `pushPathByName` changes a `@State`/`@Local` variable mid-render (`AceStateMgmt: State variable '...' has changed during render!`).
- `windowStage.loadContent('pages/Index')` (Index is an example; use the actual page name of the project) must name a page that is registered in `main_pages.json`'s `src` array AND exists on disk as `pages/Index.ets` — loadContent path, registration entry, and file name are the same string in all three places. An unregistered or nonexistent path fails to load at runtime: the app does not crash but boots to a blank screen, with no compile-time diagnostic. Name the page once, then reuse that name in all three spots.
- `.hideNavBar(true)` hides the whole NavBar (title bar + content + toolbar), not just the title. In Stack mode the NavBar IS the home content — `hideNavBar(true)` there blanks the home page (Navigation children → 0, white screen). To hide only the title use `.hideTitleBar(true)`; reserve `.hideNavBar()` for Split mode or a host that shows destinations only.

## Strict typing
- Every object literal needs explicit type context: a typed variable, typed parameter, or declared `interface`/`class`. Never a bare `{ key: value }` (`arkts-no-untyped-obj-literals`), and never object-literal syntax as a type (`arkts-no-obj-literals-as-types`).
- Banned: `any`, `unknown`, `ESObject`, lowercase `object` as any type position, index signatures, bare `{}` fallbacks, anonymous/inline object types, TS utility types (`ReturnType`, `Pick`, `Omit`, `Parameters`, `Exclude`, `Awaited`), type-position `typeof`, type predicates (`value is T`), non-null `!`, `require(...)`, dynamic `import(...)`, `var`, destructuring declarations/params, function/class expressions, generators, JSX, `with`, `as const`, constructor parameter fields, `delete`, `in`, `for..in`, `obj[key]` on non-Record (`arkts-no-props-by-index`), `Reflect.get`, `hasOwnProperty`, `.call`/`.apply`/`.bind`, `Object.entries`, and `.values()` on an enum. `Record<K, V>` is NOT banned — it is the recommended replacement for index signatures and dynamic-key maps (`arkts-no-indexed-signatures`). Use `Record` with quoted keys: `{ 'k': v }`. `Partial<T>`, `Required<T>`, and `Readonly<T>` are NOT banned — they are supported utility types (T must be a class or interface for `Partial`).
- Declare named `class`/`interface` models with explicit fields, params, returns, and generics. Use `===`, `!==`, `?.`, `??`; normalize optional numbers before math.
- Hoist helpers to file scope or named static methods — no nested/local function declarations. Static and exported helpers never use `this` (`arkts-no-standalone-this`).
- Treat `JSON.parse`, Preferences, router params, AppStorage, and SDK callbacks as opaque until normalized by `typeof`/null checks. Cast parsed JSON once to a named raw model (`JSON.parse(raw) as TaskRawInput`), then validate and copy fields into strict models. Never probe with `'field' in data`, `obj[key]`, or `Object.keys(...)+index`; for dynamic arrays hold elements as `Object`, check `typeof`, then push into a typed array. Never pass a string literal where an enum is expected.

## Component attributes and enums
- Every chained attribute must exist on that component's `XAttribute` type — do not invent one, and do not borrow a neighbour's. Frequent misses: `Stack` uses `.alignContent(Alignment)` while `.justifyContent()` belongs to `Row`/`Column`/`Flex`; minimum size is `.constraintSize({ minWidth })`, not `.minWidth()`/`.minHeight()`; `.hideNavBar()` is on `Navigation`, not `NavDestination`, and `Navigation` has no `.onReady()` — destinations come from the system route table (single-builder `.navDestination` fallback only); `List` uses `.alignListItem(ListItemAlign)` (not `ListItemAlignment`) and has no `alignItems`/`listItemGap`; style `Tabs` bars with `BottomTabBarStyle`/`SubTabBarStyle` via `TabContent.tabBar()`, not `.barActiveColor()`/`.selectedColor()`; `Slider` uses `.gesture()` not `.onGesture()`; `TimePicker` uses `.textStyle(PickerTextStyle)` not `.fontSize()`; security components such as `SaveButton` accept `.padding()` but not `.margin()`.
- Bottom tabs use `Tabs({ barPosition: BarPosition.End })` and `TabContent.tabBar(BottomTabBarStyle.of(icon, label))` so the label is a visible bar node. Do not wrap a custom `@Builder` in `.tabBar(() => { ... })`, and do not size that builder root with `.height('100%')` — the bar slot stays empty. When a locator id is required, pass the builder directly to `.tabBar()`, put `.id()` on its root, and give that root a fixed height equal to `.barHeight()`.
- Enum member names and casing must match the SDK exactly (`ButtonType.CAPSULE`, `TouchType.Up`, `LineCapStyle.Round`, `BlurStyle.Thin`, `GradientDirection.RightBottom`, `DialogAlignment.Center`). `Color` offers only White/Black/Blue/Brown/Gray/Green/Grey/Orange/Pink/Red/Yellow/Transparent — no `Gold`; use a hex string or `Resource`. `Curve` has no `Spring`; take a spring curve from `@ohos.curves` via `curves.springCurve(...)`. `AppStorage` exposes `setOrCreate`/`get`/`set`/`has`, and `AlertDialog` is called as `AlertDialog.show(...)`. Verify a member exists before using it. If these rules already name that member, its arguments, and the call order, write it from the rules and do not `devecocli docs search` or `docs read` it again. For a member these rules do not specify, the only evidence is one `devecocli docs read` of that API in this session. Do not `cat`, `grep`, or `sed` SDK `*.d.ts` files to check a name.
- Match an existing overload: check argument count and types before calling, and do not pass generic type arguments to methods that take none.

## Async and SDK namespaces
- Never read a property off an un-awaited Promise. `await` the factory first: `preferences.getPreferences(...)`, `relationalStore.getRdbStore(...)`, `store.querySql()`, `picker.select()`, `requestPermissionsFromUser()`, `fileIo.open(...)`, `audio.createAudioCapturer(...)`. Do not use `as` to turn a `Promise<T>` into `T`; async functions return `Promise<T>`.
- Distinguish namespace factories from instance methods: `preferences.getPreferences()` returns a store whose `getString`/`putString`/`flush` are instance methods — never call them on the `preferences` namespace. Same for `relationalStore.getRdbStore()` → `RdbStore`.
- Call SDK namespace members directly with namespace-qualified types (`camera.CameraDevice`, `image.PixelMap`, `geoLocationManager.Location`). Do not assign a namespace import to a variable, boolean-check it, or emit a bare token statement like `huks;`. Do not mix callback and Promise forms of the same API.

## Document picker
- `picker.DocumentViewPicker` comes from `@kit.CoreFileKit`. `await documentPicker.select(...)` returns document URIs (`file://docs/...`), not filesystem paths.
- `listFileSync` / `openSync` / `statSync` / `accessSync` need `new fileUri.FileUri(uri).path` first. `persistPermission` does not convert the URI; passing the raw URI throws `No such file or directory`.
- A folder scanned again after restart must persist the original URI: `fileShare.persistPermission([{ uri, operationMode: fileShare.OperationMode.READ_MODE }])`. Declare `ohos.permission.FILE_ACCESS_PERSIST` in `module.json5` (a name entry, no reason string). Without that declaration the call is denied, the grant dies on the next process, and the directory row stays while `listFileSync` returns nothing. Store the URI and the `.path` separately. In `aboutToAppear` / `onCreate` / `onWindowStageCreate`, `await fileShare.activatePermission([{ uri, operationMode: fileShare.OperationMode.READ_MODE }])` on each saved URI and only then call `rescan()` — activation inside `rescan` or beside `listFileSync` does not count. `READ_AUDIO` does not replace these two calls or this declaration. A one-shot read in the same callback needs neither.
- If `persistPermission`, `activatePermission`, or `listFileSync` throws, stop on a permission error and keep the previous library. Do not catch-and-continue into an empty song list, and do not write that empty list back to the cache. An empty `catch` around `persistPermission` is that failure.
- `listFileSync`, `statSync`, and `accessSync` use the persisted `FileUri.path` after `activatePermission`. Do not pass that docs fd to `AVPlayer`: the media service treats `/storage/Users/...` as a cloud fd and `prepare` fails with `GetDuration -1`. `copyFileSync` into `cacheDir` or `filesDir`, `openSync` the sandbox file, and use that fd for `AVPlayer.fdSrc`. Keep that `fileIo.File` until `player.release()`.

## AVPlayer
- `media.createAVPlayer()` from `@kit.MediaKit` starts in `idle`. Register `on('stateChange')` and `on('error')`, and arm `waitFor('initialized')`, before assigning `url` / `fdSrc` / `dataSrc` or calling `setMediaSource`. Setting the source moves the player to `initialized` inside that assignment; a listener or waiter created afterwards misses the transition and the wait times out.
- Drive `prepare` / `play` / `pause` / `stop` / `seek` from `stateChange` or `player.state`, not from a local enum. `prepare` only in `initialized`; `play` / `seek` / `stop` in `prepared` / `playing` / `paused` / `completed`; `pause` in `playing` / `paused`. Do not call `prepare()` in the same turn as assigning `fdSrc` or `url`. `reset` and `release` are lifecycle calls and are not gated by this table.
- Keep the `fileIo.File` from `open` on a field until after `player.release()`. Storing only `file.fd`, or calling `closeSync` before `release` (including inside `stop()`'s `finally`), closes the descriptor while the player still holds it.
- Assign `loop` only in `prepared`, `playing`, `paused`, or `completed`. Assigning it in `idle` or `initialized` throws `5400102` synchronously. If that assignment shares a `try` with `fdSrc`, the load aborts before the source is set and the track is treated as unplayable. Set `player.loop` in the `prepared` branch. That throw is a state error — do not skip the track for it.
- `AVPlayer.fdSrc` and `AVMetadataExtractor.fdSrc` must both be `{ fd: file.fd, offset: 0, length: stat.size }` after `fileIo.statSync` on the opened file. Never assign the `fileIo.File` returned by `openSync()` to `fdSrc`. The docs sample `fdSrc = fileIo.openSync(...)` is not the call shape — rewrite it to the object form before using it. `{ fd }` alone leaves the length unknown and the demuxer rejects the file. `AVPlayer` must `copyFileSync` a DocumentViewPicker path (`/storage/Users/...`) into the sandbox before this open. `AVMetadataExtractor` may `openSync` that docs path directly, but its `fdSrc` is still `{ fd, offset, length }`.
- Set `currentSong` to the track the user picked before `prepare` finishes. If `copyFileSync`, `openSync`, or `prepare` fails, keep that song selected and keep the error text until the next successful load. Do not clear the error after a few seconds, and do not leave the title as `未在播放` while the queue is non-empty.
- `AVMetadata.duration` from `fetchMetadata()` is a `string` of milliseconds, the same kind of field as `title` and `artist`. `typeof metadata.duration === 'number'` is always false, the assignment is skipped, and the row stays `00:00`. Store `Number(metadata.duration)` when that value is finite and greater than 0. `AVPlayer.duration` is a `number`; do not parse that one. If `fetchMetadata` throws, keep the filename and leave duration unset; an empty `catch` that stores `0` makes every row `00:00`.

## Platform basics
- If a permission, service, or device capability is unavailable, still render a graceful failure state and preserve existing data.
- Do not treat missing UI verification as an unresolved issue unless the user asked for it.
